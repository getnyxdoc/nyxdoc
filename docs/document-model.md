# Document and revision model

## 문서 상태

문서는 본문을 가진 동시에 다른 문서를 담는 트리 노드다. 별도 폴더 타입은 없다.
`parent_document_id`와 `tree_order`가 부모·형제 순서를 표현한다.

사람이 새 문서를 만들 때 제목은 저장의 선행 조건이 아니다. 비어 있는 제목은
`제목 없는 문서`로 정규화한다. 본문의 첫 줄은 AST 본문으로 유지하며 제목으로 자동 이동하지
않는다. 제목을 암묵적으로 추론해 문서 의미를 바꾸는 대신 사용자가 나중에 명시적으로
이름을 바꿀 수 있게 한다.

현재 본문의 정본은 AST v2다. `document_blocks`의 각 활성 행은 최상위 AST 블록 하나와 검색용
평문을 함께 보관한다. 모든 요소는 안정적인 ID를 가지며 내부에는 rich text, 링크, 내부 문서
참조, 이미지, 코드 블록, 목록, 표를 담을 수 있다.

문서 메타데이터는 `document_type`, `workflow_status(draft|review|final)`, `tags_json`이다.
운영상 `documents.status`의 `active|archived`와 작성 단계인 `workflow_status`는 서로 다른 개념이다.

## 공유 초안과 리비전

활성 문서는 generation별 Yjs 공유 초안을 하나 가진다. 사람의 웹 편집과 에이전트의 MCP/REST
수정은 같은 초안을 바꾸며 `draftVersion`은 에이전트 명령의 낙관적 기준이다. Yjs 업데이트는
계속 저장되고 브라우저에는 IndexedDB 사본이 남는다. 네트워크 단절, 유휴 시간, 화면 닫기,
재접속은 정본 저장으로 취급하지 않는다.

사용자 저장·`Ctrl/⌘+S` 또는 에이전트 `commit_document`만 현재 공유 초안을 정본으로 스냅샷한다.
내용이 달라졌다면 문서별 단조 증가 번호를 가진 리비전 하나를 만들고, 리비전은 다음을 고정한다.

- 전체 AST 본문 스냅샷
- 제목과 부모 문서 위치
- 문서 유형, 작업 상태, 태그
- 기준 리비전, 변경 요약, 행위자, 출처, 생성 시각

과거 조회와 diff는 읽기 전용이다. 복원은 선택한 상태를 공유 초안에 불러올 뿐 리비전을 만들지
않는다. 사람이 검토하고 명시적으로 저장해야 과거 내용이 새 정본 리비전이 된다. 기존 번호와
스냅샷은 언제나 바뀌지 않는다.

## 에이전트 쓰기

`agent_credential_write_requests`는 `(credential_id, request_id)`별 요청 해시와 최초 결과를 저장한다. 동일 요청
재전송은 최초 결과를 반환하고, 같은 ID를 다른 payload에 쓰면 거절한다.

부분 수정은 안정적인 최상위 블록 ID를 대상으로 공유 초안에 순서대로 적용된다. 에이전트는
`get_working_document`에서 읽은 최신 `draftVersion`을 `expectedDraftVersion`으로 보내고,
오래된 값은 `DRAFT_CONFLICT`로 거절된다. 정본 저장 시 초안이 시작된 `baseRevisionNumber`와
현재 정본이 다르면 `REVISION_CONFLICT`로 거절되며 서버가 rich AST를 조용히 자동 병합하지 않는다.

## 참조와 미디어

`doc_ref`가 저장될 때 `document_references` 역색인을 같은 트랜잭션에서 갱신한다. 대상 문서는
같은 워크스페이스의 활성 문서여야 하며 범위 제한 연결은 허용된 트리 밖을 참조할 수 없다.

이미지 바이너리는 `media_assets`와 파일 저장소에 있고 AST에는 `mediaId`와
`/api/media/{id}`만 남는다. data URL은 허용하지 않는다. 외부 에이전트는 MCP에서
`create_image_upload`로 5분짜리 일회용 업로드 권한을 발급받고 원본 바이트를 별도 HTTP
`PUT`으로 전송한다. 권한은 연결 키, 워크스페이스와 선택적인 대상 문서에 묶이며 사용 시점의
최신 멤버십·세부 권한·문서 범위를 다시 확인한다. 성공 응답의 `imageBlock`만 초안에 넣는다.

## 변경 이벤트와 연결 키

리비전과 같은 트랜잭션에서 `document_events`가 만들어진다. 워크스페이스 전역 `cursor`를 통해
외부 에이전트가 사람이나 다른 에이전트의 변경을 이어 읽는다. 읽은 위치는 전역 연결 키와
워크스페이스의 조합별로 분리되어, 같은 키가 다른 워크스페이스의 커서를 덮어쓰지 않는다.

API 토큰 원문은 생성 시 한 번만 보이고 DB에는 SHA-256 해시만 저장한다. 토큰은 읽기, 초안 쓰기,
정본 commit, 변경 피드, 리비전 복원 스코프와 선택적인 `root_document_id`를 가진다. 루트가 있으면
해당 문서와 그 하위 트리만 노출된다.

## 불변 조건

1. 문서·부모·내부 참조·미디어는 같은 워크스페이스에 속한다.
2. 에이전트 초안 쓰기는 최신 `draftVersion`, 정본 commit은 최신 `baseRevisionNumber`를 요구한다.
3. 초안 저장은 리비전/이벤트를 만들지 않고 명시적 정본 변경 하나만 리비전 하나와 이벤트 하나를 만든다.
4. 문서, 블록, 참조 색인, 리비전, 이벤트, 멱등 결과는 한 즉시 트랜잭션에서 갱신된다.
5. 내용이 같으면 `unchanged`이며 새 리비전이 없다.
6. 문서 트리는 자기 자신이나 자기 자손을 부모로 삼을 수 없다.
7. AST 안의 모든 요소 ID는 문서 내에서 유일하고, 블록 ID는 저장소 전체에서 충돌하지 않는다.
8. 에이전트 이미지 업로드 권한은 짧게 만료되고 한 번만 사용되며 원본 비밀값은 DB에 저장하지 않는다.
