# Agent To-do

Agent To-do는 사람이 떠오른 문서 요청을 미리 남겨두고, 외부 에이전트가 나중에 Nyxdoc에
연결해 안전하게 이어서 처리하기 위한 작업 목록이다. 각 작업의 데이터·권한 경계는 하나의
워크스페이스에 속하지만, 에이전트는 먼저 워크스페이스를 고르지 않고 자신에게 할당된
모든 허용 워크스페이스의 작업을 한 번에 조회한다. Nyxdoc이 에이전트를 실행하지는 않는다.
사용자가 자신의 Codex, OpenClaw 같은 에이전트에게
“Nyxdoc의 Agent To-do를 처리해줘”라고 명시적으로 요청해야 작업이 시작된다.

## 담당 지정과의 차이

- 담당 지정은 `이 문서를 계속 주도·공동 작업·검토한다`는 장기 책임이다.
- Agent To-do는 `이 내용을 보강한다`처럼 시작과 완료가 있는 유한한 요청이다.
- 둘 다 접근 권한이 아니다. 연결 키의 grant binding과 scope, 워크스페이스 grant
  capability, IP 제한과 선택적 문서 하위 범위를 모두 통과해야 실제 문서를 읽거나 쓸 수 있다.
- MCP 연결, 작업 목록 조회, 상세 읽기 또는 작업 발견은 실행 허가가 아니다.
- 사람이 에이전트에게 Nyxdoc Agent To-do 처리를 명시적으로 요청한 경우에만
  `claim_task`를 호출한다. 그런 요청이 없으면 에이전트의 기본 행동은 대기다.

## 작업 내용

최소 입력은 한 줄 제목이다. 다음 정보는 필요할 때 보완한다.

- 설명과 완료 조건
- 설명·완료 조건에 붙이는 스크린샷
- 낮음·보통·높음·긴급 우선순위
- 대상 문서 또는 워크스페이스 전체에서 작성할 새 문서
- 담당 에이전트 또는 미할당
- 에이전트 결과 제출 뒤 사람 확인 필요 여부
- 진행률과 막힌 이유
- 결과 요약, 결과 문서와 불변 리비전

기본값은 담당 미지정, 보통 우선순위, 사람 확인 필요다.

스크린샷은 설명과 완료 조건 입력란에 클립보드로 붙여넣거나 파일 선택으로 추가한다.
브라우저는 이미지를 `/api/media`에 multipart로 업로드하고, Agent To-do에는 base64 본문이
아니라 `mediaId`, 용도(`description|acceptance_criteria`)와 정렬 순서만 저장한다.
한 작업에는 최대 20개를 첨부할 수 있다. Task, 대상 문서와 media가 모두 같은
워크스페이스인지 서비스와 DB 무결성 제약에서 함께 검증한다.

## 상태

```text
ready → in_progress → review → completed
                     ↘ completed
          ↕ blocked
```

- `ready`: 화면의 **To-do**. 아직 에이전트가 가져가지 않은 상태
- `in_progress`: 한 에이전트가 선점해 작업 중
- `blocked`: 막힌 이유와 함께 대기
- `review`: 화면의 **확인 필요**. 에이전트가 결과를 제출했고 사람 확인이 필요함
- `completed`: 사람 확인까지 끝났거나 확인 없이 완료됨
- `cancelled`: 사람이 취소함

모든 상태 변경은 낙관적 `version` 검사로 동시 변경을 보호하고, 행위자·시각·메시지와
함께 불변 작업 이력 및 워크스페이스 감사 로그에 남는다. 에이전트 쓰기는 `requestId`로
멱등하게 재시도할 수 있다.

## 사람 흐름

문서 목록 위의 **Agent To-do**에서 현재 열린 요청 수를 확인한다. **＋**를 누르면 현재 문서를
대상으로 한 한 줄 요청을 바로 만들 수 있다. 상세 화면에서는 담당 에이전트, 대상 문서,
우선순위, 완료 조건과 사람 확인 여부를 정하고 작업 이력 및 결과 리비전을 확인한다.

에이전트가 `review`로 제출한 작업은 사람이 결과 문서와 리비전을 확인한 뒤 **확인 완료**로
확정한다. 완료·취소 작업은 다시 `ready`로 열 수 있다.

## 에이전트 흐름

1. `list_my_tasks`로 자신에게 할당된 모든 허용 워크스페이스의 작업을 확인한다. 각 작업의
   `workspaceId`, `workspaceName`, `workspaceSlug`로 대상 경계를 알 수 있으며 미할당 작업은
   `includeUnassigned: true`를 명시한 경우에만 함께 조회한다.
2. 작업의 설명·완료 조건과 첨부 media를 같은 워크스페이스 권한으로 읽는다.
3. 사용자가 작업 처리를 명시적으로 요청한 경우에만 `claim_task`로 하나를 선점한다.
4. 문서를 읽고 공유 초안을 수정한 뒤 필요하면 `report_task`로 진행률이나 막힘을 남긴다.
5. 변경 내용을 검토하고 `commit_document`로 정본을 명시적으로 저장한다.
6. `complete_task`에 결과 요약과 결과 문서·리비전을 함께 제출한다.

`get_task`, `claim_task`, `report_task`, `complete_task`는 Task ID에서 대상 워크스페이스를
자동 판별하므로 MCP 연결의 워크스페이스를 바꿀 필요가 없다. `create_task`로 후속 Agent
To-do를 만들 때만 `workspaceId`를 명시한다. 생성만으로 실행되지는 않는다. 각 단계는 해당
워크스페이스 grant의 capability·문서 범위를 다시 검사한다. 문서 하위 범위 grant는
해당 범위 안의 대상 문서가 있는 작업만 볼 수 있고 워크스페이스 전체 작업을 만들 수 없다.
