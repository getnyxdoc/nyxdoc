# Nyxdoc editor redesign

## 결정

현재 `textarea`와 `input`을 조합한 편집기는 기능을 더 붙이지 않는다. 인증, 문서 트리,
리비전, 변경 이벤트, MCP/REST 경계는 유지하고 본문 편집기와 본문 표현만 단계적으로
교체한다.

새 편집기의 기준은 다음 세 문장이다.

- 화면과 블록 조작은 Notion처럼 단순해야 한다.
- 글쓰기와 표의 기본기는 Google Docs나 Word 수준으로 예측 가능해야 한다.
- 문서 ID, 블록 ID, 리비전, 변경 커서는 Nyxdoc이 소유하고 사람과 에이전트가 같은 기록을 본다.

편집 엔진의 첫 구현 후보는 Plate 53이다. Plate의 공식 플러그인이 다중 블록 선택,
목록 들여쓰기, 글자 크기, 문단 정렬, 표 그리드 선택과 셀 복사·붙여넣기를 제공하고,
React 19를 지원하기 때문이다. 엔진을 Nyxdoc 데이터 모델로 삼지는 않는다. 아래의 제한된
JSON 스키마를 Nyxdoc 계약으로 두고 Plate는 그 계약을 편집하는 어댑터로 사용한다.

## Editor Baseline

기능을 사용자가 하나씩 발견하는 방식으로 개발하지 않는다. 아래 P0 항목을 하나의
출시 단위로 보고, 자동 검증과 수동 확인을 모두 통과하기 전에는 기존 운영 편집기를
교체하지 않는다.

### P0: 운영 편집기 교체 조건

#### 입력과 선택

- Enter로 새 문단, Shift+Enter로 같은 블록 안 줄바꿈
- 마우스와 Shift+방향키로 여러 줄·여러 블록 선택
- 한글 IME 조합 중 Enter, Backspace, 자동 변환이 조합을 깨뜨리지 않음
- 실행 취소와 다시 실행, 브라우저 안팎의 일반 텍스트·HTML 복사와 붙여넣기
- 클립보드 이미지를 바이너리 파일로 업로드하고 문서에는 인증된 미디어 링크만 저장
- 빈 문단, 문서 처음과 끝, 선택 범위 삭제와 병합의 일관된 동작

#### 텍스트와 문단

- 굵게, 기울임, 밑줄, 취소선, 인라인 코드, 링크
- 글자 크기, 글자색, 배경색
- 왼쪽, 가운데, 오른쪽, 양쪽 정렬
- 제목 1~3, 본문, 인용, 콜아웃, 구분선
- 선택 영역 전체에 서식을 적용하고 혼합 상태를 툴바에 표시

#### 목록과 블록

- `-`, `*`, `1.`, `[]` 입력 규칙과 `/` 명령
- 글머리, 번호, 할 일 목록의 Enter 종료, Tab 들여쓰기, Shift+Tab 내어쓰기
- 블록 여러 개 선택, 이동, 복제, 삭제

#### 표

- Tab/Shift+Tab과 방향키 이동
- 마우스 드래그와 Shift+방향키로 여러 셀 선택
- 선택한 셀의 복사, 잘라내기, 붙여넣기, 일괄 삭제와 서식 적용
- 열 너비 조절, 셀 병합과 나누기
- 표 안 여러 문단과 줄바꿈, 표 앞뒤에서 커서 이동

#### 저장과 접근성

- 모든 최상위 블록, 표 행, 표 셀에 안정적인 ID
- 저장 → 읽기 → 저장 JSON 왕복 시 의미와 ID가 바뀌지 않음
- 저장 실패, 리비전 충돌, 이탈 전 미저장 상태가 화면에 명확히 보임
- 키보드만으로 핵심 명령 수행, 버튼 이름과 포커스 표시 제공
- 읽기 화면과 편집 화면에서 같은 내용과 정렬·서식·표 구조 표시

## Nyxdoc Document AST v2

저장 형식은 HTML이 아니라 버전이 있는 JSON AST다. Plate/Slate와 가까운 모양을 사용해
브라우저 편집 과정에서 불필요한 변환을 줄이되, 허용하는 노드와 속성은 Nyxdoc이
명시적으로 제한한다.

```json
{
  "schemaVersion": 2,
  "blocks": [
    {
      "id": "block-1",
      "type": "p",
      "align": "left",
      "children": [
        { "text": "사람과 ", "fontSize": "16px" },
        { "text": "에이전트", "bold": true, "fontSize": "16px" },
        { "text": "가 함께 읽습니다." }
      ]
    }
  ]
}
```

### 노드 규칙

- 최상위 텍스트 블록은 `p | h1 | h2 | h3 | blockquote | callout`이다.
- `hr`은 내용 없는 구분선이다.
- 목록은 별도 중첩 DOM이 아니라 텍스트 블록의 `listStyleType`, `indent`, `checked`로
  표현한다. 이 방식은 블록 ID를 유지하면서 들여쓰기를 바꾸기 쉽다.
- 표는 `table > tr > td|th > text block` 구조이며 행과 셀도 ID를 가진다.
- 이미지는 `img` 최상위 void 블록이며 `mediaId`와 `/api/media/{mediaId}`만 원본으로
  저장한다. `data:` URL과 외부 URL은 저장 계약에서 거절한다.
- 링크는 `a` 인라인 요소다. 나머지 인라인 내용은 텍스트 leaf다.
- 검색용 일반 텍스트는 AST에서 파생한다. 일반 텍스트가 원본이 될 수 없다.
- 알 수 없는 노드나 속성을 조용히 버리지 않고 검증 오류로 처리한다.

### 저장소 전환안

검증이 끝난 뒤 DB에 다음 변경을 한 번의 마이그레이션으로 적용한다.

1. `documents.content_schema_version`을 추가한다.
2. 각 `document_blocks` 행에 Nyxdoc 최상위 노드 하나를 담는 `content_json`을 추가한다.
3. 기존 `content` 열은 검색용 파생 일반 텍스트로만 유지하며 외부 계약에 노출하지 않는다.
4. v2 문서에서는 `content_json`만 원본이며 `metadata_json`은 더 이상 원본으로 쓰지 않는다.
5. 리비전 `snapshot_json`은 배열 대신 `{ schemaVersion, blocks }` 전체를 저장한다.

문서 하나를 단일 거대 행으로 바꾸지 않고 최상위 블록 행을 유지하는 이유는 기존의
안정적인 블록 ID와 버전, 삭제 표시, 미래의 블록 단위 에이전트 명령을 보존하기 위해서다.
한 문서의 블록, 리비전, 이벤트 갱신은 지금처럼 하나의 즉시 트랜잭션으로 처리한다.

### API 계약

- 웹, REST, MCP는 모두 AST v2 `content`만 읽고 쓴다.
- 평면 문자열 블록 입력과 호환 출력은 제공하지 않는다.
- 에이전트는 안정적인 노드 ID를 유지하고 공유 초안의 `draftVersion` 충돌 규칙을 따른다.
- 초안 patch와 정본 `commit_document`는 분리한다.
- 이후 `replace_block`, `insert_blocks`, `update_table_cells` 같은 의미 단위 명령을 추가해
  에이전트가 매번 문서 전체를 보내지 않아도 되게 한다.

## 구현 단계와 게이트

### 현재 구현 상태 (2026-07-13)

- AST v2의 엄격한 Zod 스키마, 검색용 일반 텍스트 투영과 중복 ID 검사가 있다.
- 인증된 `/app/editor-lab`에서 여러 줄/블록 선택, 부분 글자 크기, 문단 정렬,
  목록 입력 규칙과 들여쓰기, 표 그리드 선택·복사·붙여넣기·병합·나누기를 검증할 수 있다.
- `/` 명령은 본문, 제목, 목록, 인용, 콜아웃, 구분선과 표를 검색해 적용한다.
- 클립보드 이미지는 object URL로만 잠시 미리 본 뒤 multipart 바이너리로 업로드하고,
  워크스페이스별 인증 링크로 교체한다. 파일은 `data/media`, 소유권·해시·MIME·크기는
  `media_assets`에 저장하며 같은 워크스페이스의 동일 파일은 SHA-256으로 중복 제거한다.
- `0006_document_ast_v2` 마이그레이션으로 문서 스키마 버전과 최상위 블록별 `content_json`을
  저장한다. 기존 문서는 읽을 때 v2로 승격하고, 새 편집기로 저장한 문서는 AST v2 전체를
  리비전 스냅샷에 기록한다.
- 실제 `/app`의 읽기·편집 화면이 같은 Plate 기반 렌더러와 AST v2 계약을 사용한다. 표나 이미지,
  구분선이 문서 끝에 오면 클릭 가능한 빈 문단을 보장하고, 표의 가로 스크롤 컨테이너가 불필요한
  세로 스크롤바를 만들지 않는다.
- `/app`은 권한이 있는 사람에게 항상 편집 가능한 화면을 제공한다. Plate Yjs 플러그인,
  Hocuspocus WebSocket, SQLite 초안 상태와 IndexedDB를 사용해 문자 단위 공동 편집과 재접속을
  지원한다. 자동 초안 저장은 리비전을 만들지 않고 `Ctrl/⌘+S` 또는 저장 버튼만 정본을 만든다.
- REST와 MCP `get_document`는 canonical `content`만 반환하며, `create_document`와
  `update_document`도 AST v2 `content`만 받는다.
- 링크 생성·수정·해제, 표 행·열 추가/삭제와 표 전체 삭제, 선택 영역 서식 유지가 실제
  편집기에 연결되어 있다. Chrome과 Edge에서 같은 사용자 시나리오를 실행하는
  Playwright 게이트가 여러 줄, 서식, 링크, 목록, 슬래시 명령, 이미지 multipart 업로드,
  표 범위·병합·분할·삭제·복구를 검증한다.
- 자동 출시 기준과 이번 감사에서 발견한 회귀는
  [editor quality gate](editor-quality-gate.md)에 기록한다. 블록 이동/복제, 표 머리글 전환,
  운영체제 한글 IME와 Firefox/Safari 매트릭스는 별도 호환성 게이트다.

### 1. 격리된 편집기 실험실

- 운영 `/app`과 저장 API를 건드리지 않는 인증된 `/app/editor-lab`에서 시작한다.
- 샘플 v2 문서로 사용자에게 발견된 네 문제인 여러 줄/블록 선택, 글자 크기, 정렬,
  여러 표 셀 선택을 먼저 검증한다.
- 같은 데이터 계약 위에서 목록 입력 규칙, 들여쓰기와 `/` 명령의 기본 흐름을 검증한다.
- 새 편집기의 JSON을 화면에서 내려받거나 DB에 저장하는 기능은 이 단계에 넣지 않는다.

### 2. 계약 검증

- AST 스키마 검사와 저장 투영 테스트
- JSON 왕복, 일반 텍스트 투영, 중복 ID 검출 테스트
- Playwright로 키보드, 선택, 표, 붙여넣기, 한글 IME 회귀 시나리오
- Chromium 외 최소 한 브라우저에서 수동 확인

### 3. 저장 계층 전환

- DB 백업 후 스키마 마이그레이션
- 초기 테스트 문서를 정리하고 새 문서는 v2로만 생성
- v2 웹 API와 MCP를 먼저 배포한 뒤 새 편집기를 기능 플래그로 연결
- 읽기 화면과 변경 이력 복구까지 통과하면 기본 편집기를 교체

### 4. 정리

- 운영 백업·복구 검증 뒤 실험용 편집기 경로 정리
- 공개 계약에 AST v2 이외의 문서 본문 표현을 추가하지 않음

## 자동 검증 원칙

테스트는 구현 함수의 존재가 아니라 사용자 동작과 보존되는 문서 의미를 검사한다.

- `Shift+Enter` 뒤 JSON에 줄바꿈이 있고 다시 열었을 때 같은 위치에 보인다.
- 여러 블록을 선택해 가운데 정렬하면 대상 블록만 `align: center`가 된다.
- 일부 글자만 24px로 바꾸면 선택된 leaf만 `fontSize: 24px`가 된다.
- 2x2 셀 범위를 복사해 다른 위치에 붙이면 값과 서식이 행렬로 유지된다.
- 한글 조합 중 Enter를 눌러도 중복 문자나 조기 블록 분리가 생기지 않는다.
- 클립보드 이미지를 붙여넣으면 업로드 요청은 multipart 바이너리이고 최종 AST에는
  `/api/media/{id}`만 남으며 비로그인 조회는 거절된다.
- 오래된 `draftVersion` patch는 초안·리비전·이벤트를 바꾸지 않고, 오래된 정본 기준 commit도
  정본 리비전과 이벤트를 만들지 않는다.
