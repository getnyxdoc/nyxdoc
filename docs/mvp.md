# First vertical slice

첫 버전은 외부 에이전트와 사람 사이의 완전한 문서 루프 하나를 증명한다. 자동화된 첫 참조 클라이언트는 Codex SDK지만 런타임 계약은 특정 에이전트에 종속되지 않는다.

## 시나리오

1. 인증된 사용자가 Nyxdoc에서 외부 에이전트 연결 키를 만든다.
2. 사용자는 평소 사용하는 에이전트에게 문서를 만들어 달라고 말한다.
3. 에이전트는 `get_capabilities`로 계약을 확인한 뒤 `create_document`를 호출하고 리비전 1을 만든다.
4. 사용자가 Nyxdoc 웹 편집기로 공유 초안을 보완하고 `Ctrl/⌘+S`로 리비전 2를 만든다.
5. 에이전트는 `get_changes`로 사람의 변경을 발견한다.
6. 에이전트는 최신 작업본을 다시 읽고 `patch_document`로 공유 초안을 고친 뒤
   `commit_document`로 리비전 3을 만든다.
7. 문서 상단 변경 기록에 세 행위가 순서대로 표시된다.

이 시나리오는 `npm run test:codex-e2e`에서 실제 Codex SDK를 참조 클라이언트로 사용해 자동 검증한다. OpenClaw는 동일한 `/mcp`와 Bearer 계약에 연결한다.

## 제공 범위

- 사이트 정책으로 허용 도메인·이메일 인증을 관리하는 가입, 로그인, 비밀번호 재설정
- 사용자별 개인 워크스페이스와 예시 문서
- 블록 기반 문서 읽기, 만들기, 편집
- 슬래시 명령, Markdown 목록 단축 입력, Tab 중첩, 간단한 표, 문서 내부 목차
- 문서가 폴더 역할을 하는 하위 문서 트리, 경로 표시, 생성과 위치 이동
- 사람·에이전트·시스템 행위자가 표시되는 불변 리비전
- 계정 전역 에이전트와 연결 키 생성, 한 번만 원문 노출, 수정·회전·해지
- 여러 워크스페이스에 대한 에이전트 grant, 워크스페이스별 접근 프로필·capability·문서 범위와
  연결 키 binding
- 선택적인 조직 네임스페이스, 이메일/일회용 링크 초대, owner/admin/member 역할과 평면 팀
- 조직 워크스페이스의 명시적 사람·팀 grant, 조직 소유 에이전트와 승인된 개인 BYOA
- Bearer 인증 REST API
- Streamable HTTP MCP 엔드포인트 `/mcp`
- 계정 설정의 에이전트·키 관리, 워크스페이스 설정의 배정·권한 관리와 문서 상단 변경 기록·본문 복원
- Yjs 문자 단위 동시 편집, 지속 저장 공유 초안과 브라우저 IndexedDB 오프라인 사본
- 명시적 저장에서만 정본이 되는 초안/리비전 분리와 draftVersion 낙관적 제어
- 재시도 안전한 requestId, 블록 patch와 상세 충돌 응답
- 구조화 검색, batch read, 리비전 조회·diff와 권한 분리 복원
- 코드 블록, 내부 문서 링크·backlink, 인증 미디어 링크
- 문서 유형·작업 상태·태그와 워크스페이스별 문서 트리 범위
- Markdown 편의 입출력과 Nyxdoc JSON bundle 내보내기
- 사람이 명시적으로 실행을 요청하는 Agent To-do와 설명·완료 조건의 이미지 첨부
- 사이트 소유자·관리자 전용 공개 URL·가입 정책·비밀값 제외 SMTP 설정과 사이트 감사 기록

## 성공 조건

- 인증되지 않았거나 이메일이 확인되지 않은 사용자는 워크스페이스에 접근할 수 없다.
- 각 요청은 리소스 또는 명시적 선택으로 워크스페이스를 판별하며 활성 grant, 명시적 키 binding,
  키 제한과 그 워크스페이스 capability를 모두 통과해야 한다.
- 토큰 원문은 생성 응답에서 한 번만 보이며 DB에는 SHA-256 해시만 남는다.
- 웹과 외부 에이전트의 초안 쓰기·commit은 동일한 협업 명령 경로를 사용한다.
- 자동 초안 저장, 유휴, 종료, 재접속은 정본 리비전을 만들지 않는다.
- 한 번의 실제 변경은 정확히 한 리비전과 한 변경 이벤트를 만든다.
- 오래된 초안 버전은 `409 DRAFT_CONFLICT`, 정본 기준 충돌은 `409 REVISION_CONFLICT`다.
- 과거 본문 복원은 공유 초안만 교체하고 명시적으로 저장할 때 새 리비전을 만든다.
- 다른 워크스페이스 문서를 부모로 삼거나 순환하는 문서 트리를 만들 수 없다.
- `get_changes`는 커서 이후 변경을 순서대로 반환하고 연결 키·워크스페이스 조합별 커서를 전진시킨다.
- 같은 `requestId` 재전송은 중복 리비전을 만들지 않는다.
- 범위 제한 연결은 허용된 문서 트리 밖의 조회·검색·참조·쓰기를 할 수 없다.
- 리비전 diff와 복원에는 본문뿐 아니라 제목·위치·메타데이터가 포함된다.
- 실제 Codex SDK 종단 시나리오가 리비전 `agent 1 → human 2 → agent 3`을 만든다.

## 뒤로 미룬 범위

- 여러 에이전트 제품별 자동 종단 테스트와 추가 접근 프로필
- CRDT 기반 제안 모드와 변경 승인 흐름
- SSO/SCIM, 도메인 소유권 주장, 중첩 팀과 사용자 정의 역할
- 일반 파일 첨부, 댓글, 사람 mention, toggle
- 외부 문서 커넥터와 검색 인덱스
- Client ID Metadata Document(CIMD)와 사전 등록 OAuth 클라이언트 관리 UI
- 결제, 모바일 앱, 플러그인 마켓
