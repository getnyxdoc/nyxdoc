# Nyxdoc 제품 흐름 점검 · 2026-09-08

문서 작성과 관리, Agent To-do, 저장된 보기, 계정 인증, 설정 이동, 에이전트 연결을 함께 점검했다. 우선순위는 **작업하던 화면으로 돌아가기**, **실패 후 입력을 유지하고 다시 시도하기**, **키보드로 창을 열고 닫기**였다. 확인된 문제는 로컬 코드에 반영했다.

기준 소스는 `0.25.21`의 `1bf141c`이며, 검증에는 별도 SQLite 데이터베이스와 합성 계정을 사용했다. 이 문서는 로컬 변경과 검증 기록이다.

## 확인한 문제와 반영한 동작

| 영역 | 이전에 확인한 문제 | 반영한 동작 |
| --- | --- | --- |
| 에이전트 연결 | 관리 화면에서 고른 에이전트와 연결 후 돌아갈 화면이 다음 단계까지 전달되지 않았다. | 선택한 신원과 출발 화면을 연결 창으로 전달한다. 완료·취소 후 해당 화면을 새로 읽어 연결 결과를 보여준다. |
| 문서 담당 지정 | 연결 가능한 에이전트가 없어서 설정으로 이동하면 원래 문서의 담당 지정 작업으로 돌아오기 어려웠다. | 문서·워크스페이스·담당 창 위치를 보존하고 복귀 시 담당 창을 다시 연다. |
| 설정 탐색 | 계정·조직·워크스페이스 설정 사이를 이동할 때 문서 맥락이 일부 링크에서 사라졌다. | 설정 경로 생성 함수를 통일해 문서와 복귀 주소를 전달한다. 복귀 주소는 허용된 내부 화면으로 제한한다. |
| 연결 단계 이동 | 이전 단계로 돌아가면 키 이름이나 기존 키/새 키 선택이 다시 초기화됐다. 다음 단계에서 키보드 초점이 본문으로 빠지기도 했다. | 같은 신원을 설정하는 동안 입력을 유지한다. 단계가 바뀔 때 새 질문이나 완료 제목으로 초점을 옮기고, 입력 중에는 초점을 유지한다. |
| 연결 상태 설명 | 계정에 있는 활성 키 수가 해당 워크스페이스에 연결된 키 수처럼 보일 수 있었다. | 현재 워크스페이스에 실제로 연결된 활성 키를 센다. 사용할 수 없는 신원을 지정한 링크는 오류로 설명한다. |
| 인증 | 통신 예외 후 제출 상태가 풀리지 않거나, 로그인→가입·이메일 인증 과정에서 처음 목적지를 잃을 수 있었다. | 로그인·가입·재발송·비밀번호 복구 폼의 오류와 재시도를 처리한다. 문서·초대·OAuth 승인 복귀 주소를 보존하고 외부 주소는 차단한다. |
| 문서 작업 | 생성·이름 변경·삭제·리비전 조회/복원·휴지통 작업에서 통신이 끊기면 작업 버튼이 계속 잠길 수 있었다. | 오류를 해당 작업 창에 표시하고 진행 상태를 해제한다. 생성/이름 입력을 유지하며 다시 시도할 수 있다. 삭제·복구 후 문서 목록도 갱신한다. |
| Agent To-do | 항목을 빠르게 바꾸면 늦게 도착한 이전 응답이 새 항목의 내용을 덮을 수 있었다. 생성은 성공했지만 목록 갱신만 실패한 경우에도 생성 실패처럼 보였다. | 최신 요청에 해당하는 응답만 반영한다. 목록을 열 때 새로 읽으며, 생성 완료와 후속 갱신 실패를 구분해 같은 작업을 다시 생성하지 않도록 한다. |
| 저장된 보기 | 실행·생성·삭제의 로딩 상태가 섞이고 실패 후 이전 결과가 새 결과처럼 남거나 재시도가 막힐 수 있었다. | 동작별 진행 상태를 구분하고, 새 실행 중에는 로딩을 표시한다. 실패 후 재시도와 생성 입력 복구를 지원한다. |
| 좁은 문서 화면 | 가로로 긴 문서 메뉴 안에 저장 버튼이 포함되어 메뉴 이동에 따라 화면 밖으로 밀렸다. | 저장 버튼과 동기화 상태를 메뉴의 가로 스크롤 바깥에 둔다. 390·900·1280px에서 저장 버튼이 보이는지 검사한다. |
| 대화상자 키보드 | 일부 창을 열어도 초점이 배경에 남고 Tab이 밖으로 나가거나 Esc가 작동하지 않았다. | 공통 모달로 초점 진입·창 안의 Tab 이동·닫은 뒤 초점 복귀를 처리한다. 진행 중인 요청과 한 번만 표시되는 키 화면의 닫힘 보호를 유지한다. |
| 중첩 문서 선택기 | 문서 선택 메뉴 안에서 Esc를 누르면 상위 연결 창까지 취소될 수 있었다. | 첫 Esc는 문서 선택 메뉴만 닫고 선택 버튼으로 초점을 돌린다. 그다음 Esc부터 상위 창을 닫는다. |
| 새 문서 안의 링크 편집 | 문서 저장 폼 안에 링크 폼이 중첩되어 링크 적용 후 새 문서 창이 닫히는 문제가 재현됐다. | 리치 편집기를 문서 저장 폼 바깥으로 분리하고 스크롤 스타일을 전용 영역에 적용한다. 링크 적용이 문서 저장을 발생시키지 않으며, 단축키 도움말도 상위 문서 창을 유지한 채 닫힌다. |

새로 추가한 사용자 안내는 한국어·영어·일본어에 반영했다. 키보드와 비동기 실패 수정은 기존 권한·승인 정책 및 명시적 문서 저장 방식을 따른다.

## 유지한 강점과 확인 범위

문서 초안을 함께 편집하고 명시적으로 리비전을 저장하는 핵심 동작, 문서 트리 이동, 리비전 미리보기, 사용자 공유, 새 키/기존 키를 통한 에이전트 연결을 회귀 검사했다. 실제 HTTP와 WebSocket 검사에서 공동 초안 수렴, 에이전트 세션 해지 후 쓰기 차단, 여러 문서의 미저장 초안 보존도 확인했다.

시각 검토는 기존 화면을 브라우저에서 먼저 확인한 후 진행했다. 기존 색상·레이아웃·컴포넌트 스타일을 사용했으며, 문서 상단 저장 조작과 대화상자의 조작 일관성을 중심으로 개선했다.

주요 구현 위치는 [설정 탐색](../../src/lib/settings/navigation.ts), [인증 탐색](../../src/components/auth/auth-navigation.ts), [공통 대화상자](../../src/components/ui/modal-dialog.tsx), [문서 작업 화면](../../src/components/workspace/workspace-shell.tsx), [작업 목록](../../src/components/workspace/document-tasks.tsx), [저장된 보기](../../src/components/workspace/saved-views-panel.tsx), [에이전트 연결](../../src/components/settings/agent-management.tsx)이다.

## 검증 기록

- 단위 테스트: 최종 소스에서 **89개 파일, 628개 테스트 통과**(34.42초). 설정/인증 탐색의 내부 복귀 주소와 공격적인 URL 입력 검사를 포함한다.
- 실제 HTTP 통합: `test:agent-connect-http`, `test:mcp-oauth-http`, `test:mcp-http` 통과.
- 전체 Chrome 회귀: **136개 모두 통과**(4.6분, 실패·건너뜀·재시도 없음). 최종 소스에서 기존·신규 전체 검사를 한 번에 실행했다.
- 브라우저 범위: 편집기 21, 워크스페이스 24, hardening 14, 실제 인증·협업 vertical 2, 설정 17, 연결 탐색 14, 인증 복구 13, 작업 목록 8, 저장된 보기 5, 담당 지정 1, 워크스페이스 복구·키보드 13, 설정 통신 복구 2, 언어 2.
- 연결 복귀·취소·키 노출 보호, 인증 복귀, 통신 중단 후 재시도, 작업 응답 순서, 모달 키보드, 화면 폭별 저장 버튼을 검사했다.
- 정적 검사: 최종 소스의 표준 `npm run lint`, `npm run typecheck`, `git diff --check` 통과.
- 프로덕션 빌드: 최종 변경을 포함한 Next.js build 통과. 별도 데이터베이스로 standalone 서버를 실행해 health·로그인·가입 화면의 200 응답과 개발용 fixture 네 경로의 404 응답을 확인했다.

처음 병렬 검사에서는 백업 테스트 1건이 기본 5초 제한을 초과했다. 같은 테스트는 개별 재실행에서 172ms에 통과했고, worker 수를 2로 제한한 전체 검사도 기존 timeout 그대로 통과했다. 또한 격리 HTTP 검사가 만든 Next 생성 파일이 lint 대상에 들어온 문제는 해당 생성물을 `debug/`로 정리해 해결했다. 제품 lint 설정이나 테스트 timeout을 완화하지 않았다.

## 증거와 검증 한계

로컬 실행 로그와 화면 캡처는 워크스페이스의 `debug/agent-flow-audit-20260908/`에 모았다. 주요 기록은 `final-unit-frozen.log`, `final-browser-all.log`, `final-source-lint.log`, `final-source-typecheck.log`, `agent-connect-http.log`, `mcp-oauth-http.log`, `mcp-http.log`, `final-build.log`, `production-smoke.log`다. 직접 확인한 캡처에는 수정 후 저장 도구막대·담당 창·새 문서 화면과 키보드 수정 전후의 작업 창이 있다. 초기 로딩 중 본문이 비어 있던 화면은 시각 판정 근거에서 제외했다.

브라우저 검사는 실제 백엔드를 사용하는 검사와 응답을 제어하는 UI 계약 검사를 함께 사용했다. 실제 인증/API/WebSocket을 쓰는 10개를 포함하며, 나머지는 개발 fixture 기반 UI·편집기 검사다. 통신 실패와 응답 역전은 테스트에서 의도적으로 재현했다.

이번 검증은 로컬 Chrome과 개발 서버를 기준으로 한다. 실제 SMTP 발송, 운영 배포, Compose 이미지의 설치·업그레이드 전체 절차, 모든 브라우저 및 스크린리더 조합에 대한 적합성을 인증한 것은 아니다. 배포 단계의 판정은 기존 [테스트 및 릴리스 적격성 전략](../testing-and-release-qualification.md)을 따른다.
