# 버그 기록과 진단 데이터

Nyxdoc의 상단 **버그 기록** 버튼은 편집기뿐 아니라 문서 트리, 저장·동기화,
권한·공유, 성능 문제를 한 방식으로 기록한다. 읽기 권한만 있는 로그인 사용자도
자신이 볼 수 있는 문서에서 기록할 수 있으며 공개 익명 공유 화면에는 제공하지 않는다.

## 수집 원칙

버튼을 누르는 순간 최근 90초의 진단 상태를 먼저 고정한다. 이후 대화 상자가
포커스와 선택 상태를 바꾸더라도 문제 발생 시점의 기록은 달라지지 않는다.

자동 수집 항목은 허용 목록으로 제한한다.

- 앱 버전과 소스 리비전
- 브라우저·운영체제의 큰 분류와 화면 크기 구간
- 워크스페이스 역할과 허용된 작업의 참·거짓 값
- 정본·초안 버전, 저장 여부, 동기화·검증 상태
- 요청 작업 종류, 성공/실패 분류, HTTP 상태, 소요 시간 구간
- 문서 트리 펼침·접힘·이동 같은 의미 이벤트
- 편집기 블록·선택·표 위치의 구간값과 알려진 캐럿 이상 감지 결과

자동으로 수집하지 않는 항목은 다음과 같다.

- 문서 본문, 제목, 링크 주소
- 실제 입력 문자와 키 값, 클립보드
- DOM/HTML, Yjs 바이너리, 브라우저 저장소 덤프
- 요청·응답 본문, 헤더, 쿠키, 토큰
- 전체 콘솔 로그, 원문 오류 메시지와 스택
- 화면 캡처, 로컬 경로, 이름·이메일·IP 주소

사용자가 직접 쓰는 선택 설명은 최대 1,000자이며 비밀정보를 적지 말라는 안내를
표시한다.

## 보존과 제한

- 기본 보존 기간: 30일
- 최대 payload: 256 KiB
- 수동 기록: 10분에 5회, 하루 30회
- 알려진 캐럿 감지 자동 기록: 사용자당 시간당 새 지문 20개
- 같은 자동 감지 지문: 15분 동안 한 기록의 발생 횟수만 증가

만료 기록은 새 기록 저장과 앱 시작 시 정리한다. 외부 분석 서비스로 전송하지 않고
Nyxdoc의 자체 호스팅 데이터베이스에만 저장한다.

보존 기간은 `NYXDOC_DIAGNOSTIC_RETENTION_DAYS`로 1~90일 사이에서 바꿀 수 있다.
이 기간은 실행 중인 SQLite 데이터베이스에 적용된다. 별도로 만든 백업은 백업
보존 정책에 따라 기록을 더 오래 포함할 수 있으므로 운영자가 함께 관리해야 한다.

자체 호스팅 운영자가 진단 수집을 원하지 않으면 다음처럼 전역으로 끌 수 있다.

```env
NYXDOC_DIAGNOSTICS_ENABLED=false
```

끄면 앱의 버그 기록 버튼과 자동 감지가 사라지고 모든 신규 진단 수집 API가
요청을 거부한다. 이미 저장된 기록의 로컬 CLI 조회와 삭제·만료 처리는 유지된다.

## 운영자 조회

사용자에게 표시된 `BUG-...` 코드를 받아 서버에서 다음 명령을 실행한다.

```bash
npm run diagnostics:bug -- BUG-20260730-XXXXXXXXXXXX
```

기존 `CAR-...` 캐럿 기록 조회기는 이전 기록을 읽기 위한 호환 경로로만 유지한다.
