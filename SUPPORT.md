# Nyxdoc support policy

Nyxdoc is maintained on a best-effort basis. The source license does not
include installation, operations, upgrade, customization, or development
support, and no response or fix deadline is guaranteed.

## Where to ask

- Use an issue for a reproducible Nyxdoc defect. Include the version, deployment
  method, expected behavior, actual behavior, and a minimal reproduction.
- Use community discussions for usage questions, ideas, and design proposals.
- Report vulnerabilities only through the private process in
  [SECURITY.md](SECURITY.md).
- Read [LICENSING.md](LICENSING.md) for the MIT terms and send brand-permission
  questions to `hello@nyxdoc.com`.

Do not include passwords, connection keys, private documents, production
databases, or unredacted production logs in public reports.

## Triage boundary

Maintainers may close reports that are incomplete, duplicates, deployment- or
environment-specific support requests, or outside the current product scope.
Community contributions that improve documentation or portability are welcome,
but accepting a request does not create an ongoing support obligation.

There is no announced paid support program at this time. If one is introduced,
its scope and service levels will be documented separately.
